# 项目级计算后端选择设计

## 目标

在不改变现有默认行为的前提下，允许用户在创建数学建模项目时选择 MATLAB 或 Python。MATLAB 仍是默认值；用户主动选择 Python 时，任务全程使用本地 Python，不再探测或启动 MATLAB。

## 非目标

- 本次不做基于题目内容的自动语言选择。
- 本次不改变 MATLAB 不可用时自动回退 Python 的现有策略。
- 本次不实现运行中的任务切换计算后端。
- 本次不处理算法复杂度、任务超时或文献检索限流问题。

## 用户体验

创建项目第二步的选项区新增“计算环境”选择器：

- MATLAB（默认）：保持当前行为；MATLAB 不可用时按全局配置决定是否回退 Python。
- Python：直接创建本地 Python 解释器，不启动 MATLAB。

任务创建成功后，选择结果属于该项目。页面刷新、后端重启和从检查点续跑都不得改变已经选定的计算环境。

## 数据与接口

前端提交建模任务时增加 `execution_backend` 表单字段，允许值为 `matlab` 或 `python`，默认发送 `matlab`。

后端 `Problem` 模型增加同名字段，并使用受限枚举校验。`/modeling` 接口接收该字段并传入任务执行函数。任务初始化时，字段随 `Problem` 一起写入 `workflow_state.json`。

旧任务或旧客户端没有该字段时，后端使用全局 `CODE_EXECUTION_BACKEND`，因此保持向后兼容。

## 执行链路

工作流初始化解释器时，从检查点中的任务配置读取 `execution_backend`，并将其作为显式参数传给解释器工厂。解释器工厂的优先级为：

1. 项目显式选择；
2. 全局 `CODE_EXECUTION_BACKEND`；
3. 配置默认值 MATLAB。

选择 MATLAB 时继续保留现有启动探测、警告消息、回退原因和审计文件。选择 Python 时直接初始化 `LocalCodeInterpreter`，并在任务状态中记录实际后端。

续跑已有任务时，从检查点恢复 `Problem`；如果检查点来自旧版本且没有该字段，则回退到全局配置，不迁移或改写历史文件。

## 错误处理

- 前端只允许提交两个受支持值。
- 后端对非法值返回请求校验错误，不静默猜测。
- 项目选择 MATLAB 且 MATLAB 不可用时，仍执行现有回退策略。
- 项目选择 Python 且 Python 初始化失败时，任务按现有失败与检查点恢复机制处理，不自动切换 MATLAB。

## 测试

后端：

- 未传项目选项时仍读取全局默认值。
- 显式选择 Python 时不初始化 MATLAB。
- 显式选择 MATLAB 时保持现有回退行为。
- `Problem` 的选择能写入检查点并在重新加载后保留。
- `/modeling` 能接收并传递选择值，非法值被拒绝。

前端：

- 创建项目界面默认显示 MATLAB。
- 切换 Python 后请求体包含 `execution_backend=python`。
- 现有模板、语言、格式和文件上传行为不受影响。

验证：运行相关后端测试、前端类型检查和生产构建。

## 成功标准

用户可以在创建项目时选择 MATLAB 或 Python；默认仍是 MATLAB；选择能够真正控制执行器，并在任务续跑时保持一致。
