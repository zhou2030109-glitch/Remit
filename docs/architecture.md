# Remit 架构

Remit 由 Vue 前端、FastAPI 后端（单进程，内含任务消息总线）和本地执行环境组成。

## 运行组件

- **前端**：提供任务创建、历史记录、项目工作区、模型配置和人工审批界面。
- **后端**：负责 API、WebSocket、任务编排、模型调用、文件管理和任务恢复。
- **任务总线**（`app/services/task_bus.py`）：进程内广播实时消息，暂存用户插话与取消信号；服务重启时运行中的任务会被标记为停止。
- **SQLite 消息档案**：保存有序事件、任务索引及生命周期状态，支持重启与断线重放。
- **执行器**：优先使用 MATLAB，也可回退到 Python；E2B 为可选远程执行环境。

## Agent 工作流

1. Coordinator 忠实提取题面，保存不可被返修覆盖的原题字段，并为每问生成目标、输入数据、决策变量、约束、输出、依赖、风险和验证要求。
2. Research 扫描附件结构、字段、规模与质量；文献调研会检索 → 按小问筛选
   → 抓取开放获取全文 → 提取“方法卡”（问题、方法、适用条件、原文位置），
   并记录每篇文献从被引用到被采用的完整台账。
3. Analysis 使用真实附件画像和文献证据修正逐题理解，将 `problem_analysis.json` 提交人工审批；审批卡不再用原题截断文本代替分析。
4. 方法检索器使用数据校正版分析，按领域、子领域和具体方法逐层评分，为每个正式小问返回 Top-K。
5. Modeler 为每个问题建立候选模型和验证计划；启用评审组时 Scout 读取同一批分析与候选并独立探索。
6. Coder 生成并执行代码，保存数值结果和图表。
7. Modeler 根据执行证据审查或修订方案。
8. Writer 汇总可验证结果并形成论文材料。
9. 工作流在配置的检查点等待人工确认，然后继续或回退；题意返修会携带上一版分析和累计人工意见。

## 数据边界

每个任务使用独立的 `backend/project/work_dir/<task-id>/` 目录。检查点、模型输出、代码、图表和最终文档都应保存在该目录，避免跨任务共享可变状态。

模型配置由后端环境文件加载，也可由前端在当前后端进程内临时覆盖。运行时接口只返回配置是否存在，不返回密钥本身。

## 状态、重放与返修

`services/task_state.py` 定义任务生命周期契约，出站事件使用可选的 `task_status` 字段。
旧中文系统消息只作为历史兼容路径；前后端均优先读取结构化状态。
`services/message_archive.py` 负责 SQLite 事务、索引与旧 JSON 迁移；阻塞读写通过
`services/async_io.py` 移到线程，线程结束后才释放取消中的任务锁。

持久化事件具有递增 `sequence`。`GET /messages?task_id=...&after=0&limit=200`
返回游标后的事件；省略分页参数保持原接口兼容。WebSocket `/task/{task_id}?after=0`
先订阅后重放，按数据库序号发送持久化事件，并定期补回落盘但广播失败的消息。
高频 `activity` 消息只广播，不写档案。前端按任务 ID 隔离会话，按消息 ID 合并、
按序号防止旧响应覆盖新状态，并在连接成功后重新核对审批与工作区快照。

中断恢复可以复用当前节点已完成的有效计算；人工返修必须先清除当前及下游的有效证据。
这两种操作由检查点显式区分，原始附件和有效上游产物保留。Pilot 更新正式方案后，
当前调用会重建求解配置，自动模式不再依赖审批暂停来取得新方案。

## 关键入口

### 页面运行与资源清理

- `frontend/src/pages/team/useTeamStream.ts` 独立管理 SSE 连接、重连提示、历史事件合并批次和计时器。消息结构与项目 ID 检查通过后才交给页面更新；关闭连接或卸载组件时取消待发布批次，迟到的旧连接回调不再更新页面。
- `TeamChat.vue` 负责界面状态与用户操作，不直接维护连接计时器。连续重试不会重置断线提醒的起点，事件重放仍按序号去重。
- `frontend/src/utils/browserStorage.ts` 隔离 WebView 存储权限与容量异常。主题、侧栏、草稿和旧版 Markdown 图片上下文通过此入口读写；存储失败时当前操作继续，但草稿无法保证跨刷新保留。
- `PaperEditor.vue` 在一次刷新结束后再等待 4 秒启动下一次刷新，避免慢请求叠加。组件卸载后不再创建轮询或继续初次源码加载。
- `ArtifactContent.vue` 用计算属性缓存净化后的 Markdown，预览和全文共用结果；正文或图片上下文变化时才重新渲染。
- 桌面壳通过 `/status` 的 `backend.status == running` 判断后端就绪，不把 404、HTML 页面或仅有端口监听当成成功；退出信号可中断重试间隔。

相关回归覆盖 `team-stream.test.ts`、`team-chat.test.ts`、`paper-editor.test.ts`、`artifact-reader.test.ts`、`markdown-runtime.test.ts` 与 `tests/test_desktop_readiness.py`。这些检查不验证真实模型供应商的可用性。

### 服务与工作流

#### 模型额度与审查恢复

`services/model_budget.py` 复用原阶段账本键，升级、技术恢复和重启均不清零历史尝试。求解阶段的 24 次 / 900 秒默认总上限保持不变，其中 4 次 / 240 秒保留给结果审查；编码与返修只能使用其余份额。真正的审查调用通过内部 `budget_phase=review` 作用域使用保留额度，模型文本不能改变记账归属。普通阶段仍有总上限，已批准的多问 pilot 保留原来的按题数预算规则。

每次请求开始前，剩余阶段时间必须至少达到 `LLM_MIN_REQUEST_SECONDS`（默认 60 秒）；不足时不发送请求、不消耗新预占。阶段自身计时器到期会记为额度暂停，而不是走模型服务网络重试。模型额度与代码执行额度都以 `stopped` 状态保留成果，界面显示“额度暂停”，不再提供注定失败的普通重试按钮。

通过产物校验后、调用审查前，检查点保存 `pending_model_review`。恢复时仍重新校验文件，完整产物不再次交给代码手执行，也不把未完成审查当作通过。审查恢复不会因为代码执行额度已耗尽而被提前拦截；如果实际产物校验失败，代码手自身的执行额度检查仍然有效。

`model_stage_phase` 记录当前节点在执行还是审查；旧检查点还会参考最后一次审查的 refine 决定，不能仅凭旧报告存在就宣称可用审查额度继续编码。普通恢复保留当前阶段的返修方案、审查结论与已使用返修轮次，继续未完成补件；明确重做上游时才作废对应历史。进度摘要以当前任务暂停/失败状态和持久化原因优先，避免历史日志与旧子步骤把已暂停任务显示成进行中。

审查证据从实际产物读取，不再只传前 8 个文件：最多 64 个预览，总预览内容不超过 48,000 字符，单个文件读取上限 256 KB。CSV 有行列和长度限制，截断与未预览清单均显式传给审查模型；未展示不能自动解释为文件缺失，也不等于已验证。补件指令限定在被指出的缺口，保留其他已核验计算。

`GET /modeling/{id}/model-budget` 显示当前阶段的真实调用数、等待时间与恢复位置；通过现有 resume API 的 `model_budget_extension` 字段明确确认后追加有界次数和时间。追加只针对当前未完成阶段，校验当前记录和确认编号；确认重发、响应丢失及调度失败不能重复加额度。前端使用紧凑浮层展示“追加 6 次调用 / 600 秒”，不会默认替用户批准或调用模型。测试覆盖旧账本迁移、预留份额、44 秒不足窗口、计时器分类、双击与丢失响应、审查续跑复用产物。

- `backend/app/services/project_configuration.py` 是准备阶段配置修改的统一入口。结构化项目 PATCH 更新赛事、年份、语言、执行后端和任务目标时，同步运行参数并使旧计划失效。对话只自动识别简短、明确的肯定赛事切换命令；否定、问题、引用和多赛事歧义仍由准备阶段澄清。每份新计划绑定配置摘要，启动前再次核对；旧版没有摘要的计划需重新准备。已启动项目的配置保持冻结。
- `backend/app/core/artifact_integrity.py` 独立读取 CSV，不执行模型生成的代码。质量报告通过 `artifact_relations` 声明 `keyed_column` 或 `matrix_lookup`，按字符串编号检查唯一性、覆盖、有限性、单位和逐行复制一致性。默认完整覆盖，真实子集需显式声明 `coverage=subset`。关系中的自填 `passed` 或容差不能覆盖实际差异。
- 兼容没有关系声明的产物：仅在同目录距离矩阵、完整 N−1 实体集合和唯一剩余起点对应唯一候选时，自动检查距离投影。多个可能参照时不猜测。没有覆盖到的计算明确标为 `not_covered`，一致性通过不代表源数据、公式或科学结论正确。
- 主工作流在质量报告首次更新后就调用独立校验，代码手收到具体失败反馈，在原执行预算内修复。最终门禁、恢复门禁和审查证据仍重复核对实际文件，`manual_review` 不能跳过技术错误。数值不一致归为源码和产物返修，优先于换模型，不按只补 JSON 处理。
- 保留已有的阶段累计执行额度保护：耗尽时，代码手在调用模型前抛出预算异常，进入可恢复的暂停流程；返修不能自动重置额度。

相关回归：`test_artifact_integrity.py`、`test_project_configuration.py`、`test_coder_agent_resilience.py`。它们使用模拟模型与临时目录；不调用真实模型、不修改正在运行的项目。CSV 校验有文件大小、行数、表数量和总单元格上限，越界会明确阻止验收，不能当作“已验证”。

- `backend/app/main.py`：FastAPI 应用。

- `backend/app/core/knowledge/modeling_methods.json`：Remit 自有建模方法库。
- `backend/app/core/llm/`：模型抽象与供应商实现。
